# Tests for the exported C API (package P6)

## Differential harness

`harness.c` loads one `res_digium_phone.so` outside Asterisk (with stub
Asterisk symbols), calls the exported functions with the same arguments,
and prints the results.  `run.sh` builds it, runs it against the original
binary and against ours, and diffs the two outputs:

```
export ASTERISK_INCLUDE_DIR=$PWD/dev/asterisk-24/include
cargo build
dev/tests/exports/run.sh            # exit status 0 when identical
```

Covered: `phone_utils_xml_escape` (every output length from 0 to 14),
`phone_utils_parse_uri` (with and without `transport`),
`phone_utils_str_to_uint`, `phone_utils_verify_user_agent`,
`phone_utils_get_model`, `phone_utils_shell_quoted`,
`phone_utils_filename_to_fullpath`, `dpma_asprintf`, every `dpma_config_*`
getter (no current config, and a fake config with set and empty fields),
`dpma_append_config_file_dir` (including truncation), the three transport
tables, `phone_users_line_get_name`, both handler registries (list order,
the `next` fields written into the callers' structures, module
references, removal of unknown handlers), `dpma_info_send` (technology
matching, argument passing, -1 without a match), and the
`dpma_pjsip_endpoint_is_dphone` hook.  Calls that crash the original (for
example, `shell_quoted(NULL)` or the unchecked getters with NULL) are not
made.

The stubs are generated by `run.sh` from both libraries' imports, so the
harness keeps loading as our module gains new imports.  A symbol that
needs real behavior goes in `harness.c` and in `SPECIAL` in `run.sh`.
Nothing is written to the repository; `KEEP=1` keeps the temporary build
directory.

## The original PJSIP helper against our module

This loads the original `res_pjsip_endpoint_identifier_dpma.so` into a
private instance (slot 6 here; any slot works).

1. Test configuration in `dev/run/slot6/etc/asterisk/`:

   `pjsip.conf` (the scratch install's endpoints `1001` and `1002` with
   their auths and AORs, plus `default_outbound_endpoint=dpma_endpoint`):

   - endpoint `1002`: `context=phones-ctx`
   - AOR `1002`: `mailboxes=1002@vmctx,1003@vmctx` (the endpoint has no
     `mailboxes`, so the helper falls back to the AOR's first mailbox)
   - AOR `1001`: `max_contacts=1` and `remove_existing=yes` (repeated test
     registrations replace the contact)

   `res_digium_phone.conf`, appended:

   ```
   [1001]
   type=phone
   mac=00:11:22:33:44:55
   line=1001
   line=1002

   [1002]
   type=line
   line_label=Bob PJSIP
   ```

   The phone is named after the AOR on purpose: the helper's contact
   observer looks up a *phone* named after the AOR (`phone_user_find`).

2. Build with the test hooks, install, and start:

   ```
   export DPMA_SLOT=6 ASTERISK_INCLUDE_DIR=$PWD/dev/asterisk-24/include
   cargo build -p res_digium_phone --features devtest
   dev/tests/exports/install-with-original-helper.sh
   dev/tools/ast.sh start
   ```

3. Checks (`dev/tools/ast.sh cli "..."`):

   - `module show like dpma`: the helper is running; `module show like
     digium_phone`: use count 3 (dependency and two handler references).
   - `dpmadev exports line 1001` and `... 1002`: tech `PJSIP`, secret,
     callerid, mailbox, context, authname, and `pjsip_auth` from
     pjsip.conf; `dpmadev exports objects` lists the containers with their
     reference counts.
   - Edit a password or callerid in pjsip.conf, `module reload
     res_pjsip.so`: the helper's sorcery observers update the line.
   - `python3 -I dev/tests/exports/register.py 127.0.0.1 15660 1001
     <password> "Digium D65 2_9_17"` with `core set debug 2
     res_pjsip_endpoint_identifier_dpma`: the log shows "Updating DPMA user
     '1001' uri='pjsip:...'" (the helper found the phone through
     `phone_user_find` and called `phone_user_token_set_last_info`).
   - SIP INFO: run `python3 -I dev/tests/exports/uas.py 127.0.0.1 15660 1001
     <password> "Digium D65 2_9_17" 20` in the background (it registers,
     answers one INVITE, and prints every INFO it receives), then
     `channel originate PJSIP/1001 application Wait 10` and `dpmadev exports
     info PJSIP/1001-<n> {"location":5}`; the UA prints the INFO with
     `X-Event-Name: digium.test` and the JSON body.  On a Local channel
     the command reports -1.  `dpmadev exports isdphone 1001` is 1 while
     the UA is registered.
   - `module unload res_pjsip_endpoint_identifier_dpma.so` (use count back
     to 0), `module unload res_digium_phone.so`, then load both again in
     that order; repeat.

4. `dev/tools/ast.sh stop`.
